## What lives here, and the one thing that decides it

A file is in this folder if its declaration is `indicator()`, and in `../strategies/` if it is
`strategy(`. Mechanical on purpose — **check the declaration, never the filename**:
`structure_engine.pine` reads like a strategy component but is an indicator.

🔴 **`mpc_m15_playbook.pine` was DELETED on 2026-08-15 and this is the note that says where it
went.** 270 KB of dashboard — structure, sessions, gaps, order blocks, a confirmation table — that
placed no orders, so the Strategy Tester could never score it and nothing here ever measured it.
Its `strategy()` half survives and was renamed in the same pass:
`../strategies/smc_session_sweep_strategy.pine`. ⚠ **It is also where that strategy's structure
engine was lifted from byte-for-byte**, so if that block ever has to change, change it against
`engines/market_structure/` — the canonical implementation, and now the only other copy. Recover
the indicator from git if a drawing is ever wanted back. ⚠ **Notes in this file and in
`../CLAUDE.md` still name it in the present tense** — the `f_rev15` death conditions below, and
over there the mitigated-liquidity-label input, the session-window sync and the export-mirror
diff. They are kept because each records a decision made ACROSS several files and still binding
on the survivors, but the file they name is gone. `f_rev15` in particular now exists only in
`mpc_assistant.pine`.

🔴 **The stale-armed-level defect, found 2026-08-13 by reading `mss_sweeps_luxalgo.pine`, and the reason `mss_sweeps_mpc.pine` disarms on the CHARACTER change rather than only on the opposite break.** In their file the armed direction is cleared by a sweep, a failed sweep, or the OPPOSITE BOS — and an opposite BOS needs a character change plus a second break. So: bull BOS freezes the protected low at 100, price makes a new internal low at 110, price closes under 110 (a confirmed bearish character change), and **nothing touches the armed state**. Price then wicks to 98, closes 102 green, and a *bullish* signal prints into a confirmed bearish leg. It self-heals only in the one case where the protected level and the current internal low are still the same price, which any pullback after the break destroys. **Our fork disarms on any shift against the armed direction at EITHER degree**, plus a bar-count expiry and an ATR depth cap. ⚠ **The same bug has a second entrance and it is guarded separately**: the engine writes `i_last_hl` only when it has a tracked pullback extreme, and otherwise KEEPS THE PREVIOUS VALUE rather than going `na` — so `not na(i_last_hl)` alone would arm on an iHL from an earlier cycle. The arm test requires the LOCATION to have moved on this bar. **The standing lesson is about what clears state, not about their file: a state machine is only as good as its exits, and "the opposite event will overwrite it" is not an exit when the opposite event needs two steps to arrive.**

⚠ **A `_luxalgo` or otherwise vendor-suffixed file is THIRD-PARTY reference, not our source.** It
was not ported from `mpc_assistant.pine`, no `compare_*.py` gate measures it, and it carries its
own licence header at line 1 — leave that line alone. It is here to be read, not to be edited: an
edit makes it a fork nobody can re-download, so change the CLAUDE.md and take a new copy instead.

🔴 **Two separate tracks live in this one folder and confusing them wastes a session.**
`mpc_assistant.pine` and everything extracted from it (`structure_engine.pine`, every
`*_export.pine`) is the track the 13 canonical Python engines were ported from and the track
every `compare_*.py` gate measures. `smc_engine_v2.pine` is an independent from-scratch rebuild
of the same idea, with its own detection rule and its own standing instructions below. A finding
about one says nothing about the other.

⚠ **An `*_export.pine` is half of a parity gate and has to move with its parent.** Changing
`structure_engine.pine` without landing the same change in `structure_engine_export.pine` leaves
the gate green about a file nobody uses. Rule 22: an engine change is not committed until its
`compare_*.py` has actually RUN and passed on a real TradingView export.

## 🔴 The one real defect: `f_rev15` had three ways to die and the chart-side A+ engine has four

The missing one is the one that fires on a WIN — `fibo7Touched`, price back at the leg origin. So on the 15m chart the REV row read `Pass` the moment TP3 printed, while the **1m chart kept the same leg alive at stage 4 saying TAKE PROFIT** until an opposite SOS or a continuation BOS happened along, which can be hours. Two charts, two answers, one setup. Worse than a stale row: the RE-ENTRY round trip clears the TP latches when price returns to 0.618, so a finished trade could hand the 1m a fresh AWAIT and ask for a 1m SOS on a leg the 15m had closed the book on. Fixed with `or L_tp0` / `or S_tp0` on the two death conditions — `L_tp0` **is** TP3, since `p0` is `L_high`, the leg origin, the same 0.0 the drawn fib labels TP3. ⚠ **It kills one bar LATE**: the death block runs before the fib block that sets the latch, where the 15m side kills on the bar itself. Left as is — every other value this engine ships crosses the security boundary a bar late in the same way. ⚠ **It retires the whole 1m stack together, not just the row** — `rStage` falling below 3 drops `_m15Retraced`, which is what `fiboShowAligned`, the 1m External Fib, the 1m Sniper Zone and the 1m ENTRY row all hang off. ⚠ **Nothing on the 15m moves**: every consumer of `rStage`/`rTp50`/`rDeepCode`/`rZoneLo` sits behind `_fibOneMin`, `_sn1m`, `revOn1m` or the non-15m branch of the table, checked one by one; `f_rev15` exists only in `mpc_assistant.pine` and `mpc_m15_playbook.pine`, so **no bot and no parity gate can see this.**

- `indicators/engines/mss_sweeps_mpc.pine` — **our fork of the MSS Sweeps trigger, added 2026-08-13, 1321 lines.** Keeps the IDEA from `mss_sweeps_luxalgo.pine` (after a continuation break, remember the protected swing behind it; signal when price wicks through and closes back) and replaces their structure entirely with ours. **The engine block is `structure_engine.pine` lines 27-1044 with EXACTLY ONE LINE CHANGED** — regenerate with `sed -n '27,1044p' structure_engine.pine`, then re-apply that line (below), and land any structure change THERE first. Verify the deviation is still exactly one hunk with a sequence diff, never a positional one: a comment added above the changed line shifts every line after it and a positional compare then reports ~400 false differences. What our engine buys, and it is the reason the fork exists: (1) **a second degree of structure.** Theirs has only internal-at-length-5, so it cannot ask whether a sweep points with the trend; ours has `st.dir`, and the trend filter is built on it. (2) **no repaint** — every `int_bull_bos`/`int_bear_sos` fires under `barstate.isconfirmed`, where their BOS reads the live close and can vanish intrabar. (3) **the stale-level defect is fixed** — see the entry below. 🔴 **The one deviation, and it is the whole reason there is one: `internalActive = showInternal` → `internalActive = true`.** In `structure_engine.pine` the internal state machine is gated on the *display* toggle "Show Internal Structure". That is harmless in a file whose only output is drawing, and unacceptable here, where every signal reads that engine — unticking the box to clean up a busy chart would silently stop the indicator. Forced open, so the toggle now controls drawing ONLY: the engine gates its own internal labels and lines on `showInternal` separately, which means **all three Market Structure display boxes can be unticked for a clean chart and the sweeps keep firing.** ⚠ **Re-apply after every regeneration** — a plain `sed` puts the display gate back and the symptom is an indicator that draws nothing and blames the market. **The standing lesson generalises past this file: a toggle named "Show X" is a promise that it only affects drawing, and the moment a state machine reads it, the name is a lie that costs somebody a session.** 🔴 **THE FIRST TREND FILTER REFUSED ~100% OF SWEEPS AND THE CHART READ AS "TOO STRICT" WHEN IT WAS ASKING AN IMPOSSIBLE QUESTION.** Measured off a real 15m chart: 154 levels armed, 6 raw sweeps, **6 cut, 0 signalled.** The gate was `st.dir` — the direction of the last EXTERNAL break — and the mechanism is structural rather than a tuning miss: **our internal engine is wiped and reseeded on every external break, and it reseeds tracking the PULLBACK.** After a bullish external break the internal engine's first job is the move DOWN, so its first continuation break is bearish and the level it protects is a short — inside a bullish external leg. The first protected level of every external leg therefore points AGAINST `st.dir` by construction, and the filter refused exactly those. It rarely got a second chance because the next external break wiped the cycle. **Replaced by a DIRECTIONLESS measure — `msExtRun`, the count of external continuations since the last external change of character.** In a trend that builds; in chop the structure keeps reversing and it sits at 0. The old behaviour survives as a non-default option, labelled with what it costs. ⚠ **An external SOS also sets `bull_bos`/`bear_bos` in the engine, so the SOS test must come FIRST or the run never resets.** **The standing lesson: a filter's NAME is a claim about what it measures, and this one was called "trend filter" while measuring the direction of one break. The tell was not a wrong number — it was a 100% rejection rate, which is what an impossible question looks like from the outside.**

🔴 **A FAILED TOUCH WAS BEING TREATED AS A BREAK, AND IT WAS HARDCODED.** The same run showed **51 failed reclaims against 6 sweeps**: any wick through the level that did not fully qualify RETIRED the level, so one that missed by a hair was deleted before the candle that would have swept it properly ever arrived. Split into two events — a **touch fail** (wick through, candle did not qualify; the level survives and keeps waiting) and a **break** (price CLOSED through, which always retires it, no wick required so a gap counts). `msOneShot` restores the old behaviour and defaults OFF. ⚠ **The two are counted DISJOINT in the stats table, break winning**, because a closing bar satisfies both tests and the two numbers call for opposite responses — a high touch count means the trigger is picky, a high break count means the levels are simply being taken out. ⚠ **`close > open` on the sweep candle was hardcoded too** and is now `msReqGreen`, default OFF: a genuine wick-and-reclaim often closes the other colour while still finishing on the right side of the level. ⚠ **`msMinBos` was INERT at its shipped default of 1** — a protected level cannot exist without one continuation break already behind it, so the gate was always true and looked like it was working. Default 0, and the tooltip says 2 is the first value that filters anything. ⚠ Depth cap, reclaim buffer and expiry all defaulted to 0 in the same pass.

🔴 **THE STATS TABLE ACCOUNTED FOR 75 OF 154 LEVELS AND PUT THE OTHER 79 NOWHERE.** Not a wrong number — a missing one, which is worse, because every row on screen was correct and the reader had no way to see that half the population was unmodelled. The remainder held three different fates with opposite meanings: internal structure turning against the level, an external SOS turning against it, and the level simply being **replaced** by a fresher break moving it up. "Died young" and "ordinary housekeeping" were pooled into one invisible bucket. Now three rows, counted disjoint in precedence order (internal shift first — if internal structure has already turned, the external SOS behind it is the same event one degree up), plus a **self-checking `Unaccounted` row** that must read 0 and goes red when it does not. ⚠ **A failed touch only ENDS a level when `msOneShot` is on**, so it joins the sum only then. **The standing lesson: a diagnostic that reports a SUBSET without saying so is lying by omission, and it reads exactly like a complete one. Any table that partitions a population needs a row that proves the parts add up.**

⚠ **The sweep layer and the structure layer are drawn in deliberately DIFFERENT VOCABULARY, because on a real chart they were reading as one pile of tags.** Structure draws text labels; a sweep draws a solid triangle offset off the wick by 0.5 ATR, a shaded box over the grabbed wick, the taken level relit in the sweep colour, and a background tint on the bar. The armed level is amber and 2px, not pale blue and 1px, so it does not read as another structure line. 🔴 **A refused sweep and a taken one have to differ on more than brightness, and the first attempt got this wrong twice.** A rejected sweep now sits in the SAME lane as a signal — one half-ATR off the wick — so the two line up and can be compared by eye, and then disagrees on everything else: a cross rather than a filled triangle, neutral grey rather than the direction colour, and no wick box and no bar tint. ⚠ **Grey, never a faded green or red** — a washed-out green reads as a weak BUY rather than as no trade at all. ⚠ **And the tooltip has to name the FAILING GATE.** The first version printed the external direction and the break count and left the reader to work it out, so a bearish sweep refused by a bullish trend read *"External direction: bullish / Continuation breaks: 1 (need 1)"* — two lines that both look like passes, on a marker that means no. It now leads with which gate failed, states the sweep's own direction, and marks each gate PASS/FAIL with what it needed. **The standing lesson: a diagnostic that reports the INPUTS to a decision has not reported the decision, and the reader will assume the mark is a bug rather than a verdict.** The stats table carries a two-row legend for the same reason — answering "is that mark a trade" only inside a tooltip answers it only for whoever hovers. 🔴 **An armed level drawn in ONE colour cannot say which way it is for, and that is the question a reader has first.** It shipped as a single amber dashed line whether it was a protected LOW waiting to be swept downward (a long) or a protected HIGH waiting to be swept upward (a short) — so the chart drew the setup and withheld its direction. Now the line is coloured by direction, and carries a live tag on its right end reading `▲ iHL 3891.20` / `▼ iLH 3925.40`: **direction, level type and price, on the line itself.** ⚠ **The tag is a separate object from the line and must be re-anchored every bar** — the line uses `extend.right` so its visible end moves and a label does not, and without the per-bar `label.set_x` the tag strands itself back at the arm bar. ⚠ **On a sweep the tag is REPLACED, not deleted** — a frozen `▲ TAKEN iHL 3891.20` at the sweep bar, because *"a sweep happened here"* and *"THIS level was swept"* are different facts and only the second is actionable: it is the stop. **The standing lesson: a level drawn without its identity is a line, and a reader cannot act on a line.**

🔴 **WAITING and TAKEN are two STATES of a level, and drawing them in one colour family made them the same picture.** A taken level now draws in its own pair — purple for what was a protected low, amber for what was a protected high — solid and one step thicker than the dashed armed line, and its wick box and tag move with it. ⚠ **Deliberately not a darker shade of the armed colour**: a dimmer green reads as *the same thing, fainter*, rather than as *this one is finished*, which is the entire distinction being drawn. ⚠ **The split is LEVEL versus TRADE and the two layers must not be merged again** — the taken colours carry the level (line, box, tag), while the direction colours carry the trade (triangle marker, bar tint). Mixing them is what produced the original complaint that a bullish and a bearish sweep were indistinguishable. Four states now separate at a glance: armed low, armed high, taken low, taken high. ⚠ **The four visual inputs are declared LAST in the file on purpose** and anything new must go after them: TradingView keys saved values off declaration order within each type. ⚠ **It carries the standard TRADING SESSIONS block (2026-08-13) and that block is DRAW-ONLY.** One toggle, `Show Sessions`, group `10 · Drawing: sessions`, **default OFF** — the section-10 contract in `../strategies/CLAUDE.md`. Windows, timezones and colours are hardcoded to the values every other MPC Pine runs, ✅ **verified by diffing all 14 constants against `mpc_strategy.pine` rather than retyping them.** ⚠ **Ported from the `mpc_assistant.pine` copy, not the strategy copy, and the difference is DEAD CODE ONLY** — the strategies still carry session open/close and average lines behind three flags hardcoded `false`, so those branches cannot execute; the drawing is identical and this file has a compile-token budget. 🔴 **`showHistoricSessions` is `true` here and DELIBERATELY DIFFERS from `mpc_strategy.pine`, which draws the current week only.** This file exists to be read BACKWARDS — every signal it prints is a historical one being judged — and a box that stops at Sunday 00:00 New York answers "was that sweep in London?" for this week and nowhere else. Same value `mpc_assistant.pine` runs. ⚠ **It is why `max_boxes_count = 500` had to be added to the `indicator()` declaration, and that is the part that would have been missed:** Pine defaults to **50** boxes and evicts the oldest silently, so historic shading would simply stop a fortnight back and read as a broken toggle rather than a hit ceiling — a cap that looks like a bug. 500 covers roughly 160 days of three sessions, minus whatever the swept-wick boxes hold. ⚠ **The current-week anchor (`msWeekStart`, `withinSessionDays`) is now INERT and is kept rather than deleted**, so putting the old behaviour back stays the one-word change the constant's comment promises. ⚠ **No signal, level or filter reads a session** — checked, not assumed. It cannot move a mark on the chart.

✅ **COMPILES on TradingView (Aaron, 2026-08-13).** ⚠ **NOTHING IS MEASURED** — a compile says the syntax is valid and says nothing whatever about the logic. No Strategy Tester run, no export twin, no `compare_*.py`, no Python port. Every default is legible rather than optimal, and the stats table exists so the trend filter can be judged from a chart instead of argued about.

## Standing instructions

**Do**
- Confirm swings only by the 3-candle pullback method: a swing high needs 3 consecutive candles each closing below the previous candle's low; a swing low needs 3 consecutive candles each closing above the previous candle's high.
- Reset the pullback count to zero at a new extreme if price prints a new high (while seeking a high) or new low (while seeking a low) before the count reaches 3.
- Keep detection to a single fixed constant (3). No numeric tuning inputs for detection.
- Reuse the same shared pullback-tracker type (`type PB`) for both the swing (external) engine and the internal engine — instantiate it twice, don't fork the logic.
- Gate new swing structure on a body-close break of the current trading range (BOS/CHoCH), per the corrected Stage 2b architecture — do not let swings form freely inside the range.
- Update `STRUCTURE_OS_BUILD.md` status/changelog as each stage is validated on a real chart.

**Never do**
- Do not use `ta.pivothigh` / `ta.pivotlow` or any fixed-lookback-window pivot method to detect swings in `smc_engine_v2.pine` (the from-scratch rebuild). This does not apply to `mpc_assistant.pine` / `structure_engine.pine`, which are a separate, intentionally pivot-seeded track — see Key paths above.
- Do not add numeric/tunable inputs for the detection logic itself — it must stay a zero-parameter mechanical rule.
- Do not fork the shared `PB` pullback-tracker type into two separate code paths for swing vs. internal — if the two ever need to diverge, branch inside `PB` with a flag instead.
- Do not build or validate Stage 2/3 logic on top of an unvalidated swing map — the swing detector is the foundation; get it confirmed against the real chart first.
- Do not treat a wick-only touch of a range boundary as a break — only a candle body close beyond the boundary counts (BOS/CHoCH).

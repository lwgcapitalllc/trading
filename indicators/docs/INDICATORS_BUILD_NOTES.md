## 2026-08-16 — the tooltips were paragraphs, and nobody could read a toggle off one

Aaron: *"All the tooltips, when you hover over them, they are long, technical, complicated, and
just hard to get the gist of what the toggle or the setting is for."*

He was describing a settings panel you cannot use. The worst offender ran **814 characters** —
five sentences of measured history and parity warnings before it said what the checkbox did.

**MEASURED across all 29 Pine files: 151,063 → 62,931 tooltip characters, 58% shorter.** 663
rewritten from 341 unique strings (the parent/`_export` twins and the shared engine settings
repeat), mean length 216 → 91 characters, longest 814 → 166, and **not one input tooltip is
still over 200 characters**.

**The content rule that came out of it is in `strategies/CLAUDE.md`** — say what it does and what
Off does, name the unit and what 0 means, stop. The measured results and the reasons for defaults
were not deleted, they moved to `strategies/docs/<family>.md` and the specs, which is where a
reader after *why* is already heading.

### The three things worth keeping from how it was done

🔴 **A TOOLTIP TURNED OUT TO BE HALF OF A CONTRACT, AND THE TEST CAUGHT IT.**
`test_bleg.py::test_the_meta_descs_are_the_pine_tooltips_verbatim` pins four Pine tooltips to the
lab panel's `desc` in `mpc_bleg.meta.json`, byte for byte. It went **RED on the first run** — which
is the test doing precisely the job its own docstring claims, catching a silent drift where the
panel would have gone on describing settings in words the Pine no longer used. **90 `desc` fields
across the three strategy meta files were resynced in the same commit**, so the lab panel got the
plain English too rather than being left behind.

⚠ **The first meta.json resync did cosmetic damage and it was caught by counting, not by reading.**
Round-tripping through `json.dumps` reformatted every inline array — 177 changed lines in
`mpc_sos_fade.meta.json` that had nothing to do with any description. The fix was to replace the
`desc` strings in the RAW TEXT instead. **The check that found it is the one worth reusing: diff
the file and count the changed lines that do NOT contain the field you meant to change.** It
should be zero, and it was 177.

⚠ **The safety proof is the same shape as the comment migration's**: strip every tooltip string
out of the before and after copy of each file, replace it with a placeholder, and diff. **Zero
files differed outside a tooltip across all 29.** 355 strategy tests green afterwards, and
`tools/check_active_order.py` clean on all twelve strategy files.

⚠ **The nine `label.new()` tooltips were deliberately left alone.** Those are chart hovers — the
TRADE BLOCKED popup and its siblings — carrying a live reason and a price for a setup that was
refused. They are diagnostics rather than settings, and they are the only record that a refusal
happened at all, so shortening them would delete evidence rather than noise.

## 2026-08-16 — a third of every strategy Pine was prose, and it moved to `strategies/docs/`

Aaron: *"We frequently run out of tokens in our Pine strategies… these comments should not live
in a Pine strategy file. They should live in a .md file related to the strategy file, that if AI
needs to read it in any session, it reads that file instead of trying to get it out of the actual
Pine strategy. That is just wasting tokens."*

**He was right and the size of it was the surprise.** MEASURED across all twelve files in
`indicators/strategies/` before any change:

| | bytes | share |
|---|---|---|
| all twelve strategy Pines | 2,427,073 | 100% |
| full-line comments | 809,890 | **33.4%** |
| trailing comments | 28,526 | 1.2% |

**What decided the 3-line threshold — it was measured, not picked.** The 2,155 comment blocks
were binned by length: blocks of **3+ lines hold 673,782 bytes (88% of all comment bytes)**,
while the 827 one-line blocks hold only 54,419 and the 239 two-line blocks 37,046. So the cut
buys 88% of the win while leaving every inline label where it sits, and it happens to be exactly
what Aaron asked for (*"maybe one or two comments"*).

**Result: 2,378,408 → 1,817,898 bytes, 23.6% smaller, ~140,000 tokens off a full read of the
set.** Per family, largest first: `mpc_strategy` 25.4% / 27.9% (parent / export),
`mpc_d` 28.6% / 32.0%, `mpc_h4_sweep` 26.3% / 28.8%, `mpc_realign` 24.6%, `mpc_b_leg`
20.1% / 21.0%, `mpc_bos` 19.0% / 20.4%. **`smc_session_sweep_strategy.pine` moved 1.3% and that
is not a failure** — it was written recently and was already comment-light (16 comment lines
against `mpc_strategy.pine`'s 1,435), which is the state this change is trying to get the rest to.

574 entries across 7 family docs, deduped by content hash so the parent and its `_export` twin
share one entry wherever the prose matched.

### The three things that were checked rather than reasoned about

🔴 **The proof is a DIFF, not the argument that comments cannot change behaviour.** That
argument is true, and it is precisely the confident reasoning rule 22 exists so nobody has to
trust. What actually ran: strip every full-line comment from the before and the after copy of
each file, `diff` the two. **Twelve of twelve byte-identical.** The migration script asserts the
same thing itself and exits without writing if it fails.

⚠ **`git diff` looked alarming and was not.** It reported equal counts of non-comment lines added
and removed on every clean file (17/17 on `mpc_strategy.pine`). All of them were BLANK lines
re-anchoring across hunk boundaries — the byte-identity check above is what settled it. Worth
remembering: a diff of a file whose line count dropped 25% cannot be read line-for-line.

🔴 **Three tests read these Pine files directly, and they were found by grep before the run, not
after it went red.** `strategies/python/mpc_bleg/tests/test_bleg.py` asserts on `bool lTimeUp =`
lines, on `input.float` defaults against their own `minval`/`maxval`, and on tooltips matching
`mpc_bleg.meta.json` verbatim. All three read CODE and tooltips, never comments. 355 tests across
`mpc_bleg` + `mpc_sos_fade` + `mpc_bos` green afterwards.

⚠ **Trailing comments were left on the table ON PURPOSE.** 28,526 bytes, 1.2%, and taking them
means parsing `//` out of lines that also carry string literals containing `//` — a URL, a label.
All of the win was in the full-line blocks and none of the risk was.

⚠ **NO PARITY GATE WAS RE-RUN, and that is a gap rather than a pass.** Every gate needs a fresh
TradingView CSV export, which only a human can take, and exports are git-ignored scratch. This is
proof about the SOURCE and says nothing about a run — the same limitation the 2026-08-14 bulk
reformat hit, from the same cause.

⚠ **The anchor line is the load-bearing part.** `// [doc N] <title>  -> docs/<family>.md` is what
tells the next reader an explanation exists at all. Strip the anchors and the md becomes 574
entries nobody can find their way to, which is worse than the inline prose it replaced.

Migration script (one-off, not committed): it grouped consecutive full-line comments into blocks,
protected line 1 and `//@version`, kept the block's indentation on the anchor, and refused to
write any file whose non-comment lines had moved.

## 2026-08-14 — the playbook joins the contract, and section 2 is the one thing it cannot honestly have

Aaron, reading `mpc_m15_playbook_strategy.pine` on a chart: *"I'm seeing, like, you know, ways to
configure sessions. I'm seeing some weird colors by default… let's apply our standardization."*
Both halves were true and they had different causes.

**The panel.** The file shipped with four ad-hoc groups (`Playbook Setup` / `Sessions` /
`Strategy Execution` / `Debug`) because it was built on 2026-08-11, a day before the numbered
contract landed — the same reason `mpc_realign_strategy.pine` is still off it. It now carries
**3, 4, 5, 6, 7, 8, 10, 11**. 36 inputs. **`execSizeMode` / `execFixedQty` are new**, because
section 3 is "longs/shorts, risk %, **sizing mode**" and the file only had the risk half.

**The six session inputs are GONE, hardcoded at the repo's DST-aware values**, per Aaron's standing
collapse rule (*"I don't even need to see the time frame or the colors of the sessions… I'll never
configure them"*). ⚠ **And they are the counter-example to that rule being about drawing**: these
strings DECIDE trades — the sweep pool is read off them — so hardcoding them is not a collapse of a
draw setting, it is removing a control from a value that moves money. That is the right call here
only because every Pine file in this repo has carried the identical six values since 2026-07-31, so
a divergence would be a bug rather than a configuration. **A change to one belongs in every file
that carries the block.** `10 · Drawing: sessions` is the one surviving toggle and it is
**shading only**, default OFF.

🔴 **THE FIRST PASS RECOLOURED THE SESSION SHADING AND LEFT IT AS A FULL-HEIGHT STRIPE, WHICH IS
THE MORE INTERESTING HALF OF THE SAME MISTAKE.** Aaron, same day: *"sessions take up the full
vertical zone instead of tracking where the candles are, like every other session setting I have."*
It was a `bgcolor()` call — right colours, wrong geometry — and **the geometry was carrying
information the stripe destroyed: a session box's TOP AND BOTTOM ARE THE POOL.** What London sweeps
is the top of Asia's box. So the one drawing that could have shown step 2 happening was painting a
coloured column instead. It is `mpc_strategy.pine`'s SessionInfo shape now — a box per session
round its own high and low, dotted border @40, name at the lower left. ⚠ **The box is NOT deleted
when its session ends** — it is the pool the next session hunts, and only the latch is cleared.
**The standing lesson: copying a palette is not copying a drawing. The colour was the part that was
easy to check and the part that mattered least.**

🔴 **AND THE SESSION BOXES THEN STOPPED DEAD AT 2026-08-03 WHILE EVERY OTHER DRAWING RAN BACK
FURTHER.** Aaron: *"the session zones crop off at August second. Why is that?"* Nothing was broken —
the eviction cap was **30 boxes, which is exactly ten trading days at three sessions a day**, and
2026-08-03 is ten trading days before he looked. **A cap that truncates history is indistinguishable
from a bug in the thing being drawn**, and Pine makes it worse by never erroring: go past
`max_boxes_count` and it silently drops the oldest object, so the only symptom is a chart that looks
wrong. Raised to **300 (100 trading days, ~5 months)**, and the position boxes from 25 trades to 40.

⚠ **The three families share ONE 500-object ceiling and the split is now written at the top of the
file** — boxes 20 setup + 160 position + 300 sessions = 480; labels 400; lines 120. **Whichever
number is smallest decides how far back the chart goes, and the chart gives no hint which one it
was**, so raising one means taking it from another. ⚠ **Both affected tooltips now state their own
limit** ("the last 100 trading days", "the last 40 trades"), because the place a reader meets a
truncated drawing is the panel, not the source. **This is the repo's no-silent-caps rule arriving in
a drawing layer: if a limit bounds what you can see, say so where it is seen.**

⚠ **`12 · Debug` is gone.** Its one input wrote a Pine Logs line per arm, fill, cancel, close and
refusal; Aaron cut it (*"for events, we don't need that"*). Everything it said is on the chart, from
the same `sBlk`/`lBlk` state, in the SETUP BLOCKED tooltip and the state panel — so this removes a
second reader of one fact rather than the fact. The numbering still does not close up.

⚠ **`11 · Drawing: liquidity` defaults ON, against the other draw toggles.** Aaron did not
recognise it (*"where did that even come from?"*) because it is not new — the previous session's
high and low were always drawn, bundled under *"Shade the sessions"*, and this pass split them out
and gave them a name that did not say what they were. **They are STEP 2**: the red line is the level
a short is waiting to see taken. A toggle whose title does not say which rule it draws is a toggle
nobody can place, so it is now *"Show the previous session's high / low (the sweep level)"*.

**The colours.** *"Gray, blue, and then some light orange"* was the session shading, invented in
this file rather than copied: `color.gray` / `color.blue` / `color.orange` at three different
transparencies, against A+'s `#FF5252` @92 / `#2962FF` @92 / `#FFEB3B` @90. The trade drawings had
drifted the same way — blocked tags at `#ff4dd2` instead of `#FF2E9A`, white label text where every
other file uses `#101014`, and a result label graded win/loss/breakeven against a **hardcoded
±0.1R** with `color.orange` for the middle. It has a named palette block now, copied from A+, and
`execBeBandR` (0.15, the A+ value) replaces the literal. ⚠ **The state panel deliberately keeps the
TABLE palette** (`#00E676` / `#ffde59`) rather than the position one — that is the exact crossing
`mpc_d_strategy.pine` shipped for weeks.

🔴 **SECTION 2 IS ABSENT AND THAT IS A DECISION, NOT AN OVERSIGHT — it is the one place "the same
four toggles on every strategy" cannot be honoured by porting.** Every other file runs its
structure engine on the CHART frame, so drawing it is free; H4 ported ~1,000 lines in on exactly
that basis. **This file runs the engine INSIDE `request.security`, on the 15m and the 1m, and Pine
cannot draw from in there.** A chart-frame copy ported in for the drawing would paint the *5m's*
swings while the strategy trades off the *15m's* — **a chart that disagrees with the file under
it, which is strictly worse than no drawing**, and is the "control that looks like it does
something" hazard arriving as a picture instead of a checkbox. ⚠ **The honest fix is a feature, not
a port**: return the swing PRICES through the security call and draw those chart-side. Costed at
~60 lines and not built. **Aaron's call.** `1 · Confirmation table` is absent for the ordinary
reason — no table, same as BOS, D and H4.

🔴 **THE POSITION DRAWING PAINTED THE PLAN AND NEVER TOOK IT DOWN — A LOSER LEFT A FULL-HEIGHT
GREEN BAND RUNNING TO A TARGET PRICE NEVER WENT NEAR (2026-08-15).** The reward bands are created
at the FILL, entry → target, because that is what the trade is aiming at; nothing removed them on
the close. So a −1R stop-out after one bar drew a green column down to a previous-week low, and the
chart said the trade won. Aaron found it by eye: *"price never goes down, but there is a big green
bar. I'm confused."* 🔴 **`mpc_strategy.pine` ALREADY CARRIED THE RULE IN WRITING** — *"every band
comes from the strategy's own closed-trade log, at the price the engine REALLY filled — never a fib
level it merely aimed at, so the drawing can never claim profit the P&L does not have"* — **and the
palette pass copied its COLOURS without copying that.** Fixed: on the close the target bands are
deleted, the body band is repainted entry → the real exit price, and the red band is clipped to the
worst price the trade actually SAW rather than to the stop it never reached. ⚠ **With a partial, one
band still cannot describe the trade** — it shows the runner's exit; A+ stacks a band per rung and
that machinery was not ported.

🔴 **AND A CANCELLED SETUP LOOKED IDENTICAL TO ONE THAT TRADED**, which is what made the first bug
unreadable rather than merely wrong. Most armed setups never fill, and each left a full-colour
sweep label with its zone, stop and both targets — so a green LONG sweep could sit beside a red
SHORT result with nothing saying they were different setups. Cancelled setups are faded to grey
and marked `✕` now. **The pair is one lesson: every drawing on a strategy chart is a CLAIM, and a
claim about a plan has to be withdrawn when the plan does not happen.** Both of these survived a
full standardisation pass that was looking at colours.

🟢 **THEN THE TEXT CAME OFF, AND THE RULE IT LEAVES IS WORTH MORE THAN THE EDIT.** Aaron,
2026-08-15: the session boxes carried their names (*"I already know what the colours are"* — red
Asia, blue London, yellow New York, the house shades), and every armed setup carried a `London
sweep` / `Asia sweep` label that overlapped the result label. Both are gone. **The sweep label was
restating the trade's own existence**: a setup here cannot arm without a sweep, so the words added
nothing while costing a second text box on the same candles. What replaced it draws the thing the
label only alluded to — **a dashed double-width line at the price that was actually taken, from the
bar it was taken on across to the setup**, so the reason for the trade is a level on the chart
rather than a word. **A label that names a precondition every drawn setup already satisfies is
noise; the level that precondition fired on is information.** ⚠ An armed setup now draws NO text at
all — the only text a setup ever gets is the `✕` on a cancelled one, which is the only case with
nothing else to speak for it.

🔴 **AND THE PANEL THEN CARRIED TWO NUMBERING SYSTEMS AT ONCE, WHICH MADE THE STRATEGY
UNREADABLE FROM ITS OWN SETTINGS.** Aaron, 2026-08-15: *"I don't understand the strategy that's
laid out in this pine right now. It doesn't make sense."* The group headings are the house
contract's numbers; the input TITLES had carried the video's five step numbers since the file was
built (`1 · Direction timeframe`, `4 · Zone timeframe`). Reading down the panel counted **4, 1, 2,
3, 5, 4, 6** — so a strictly ordered five-step model looked like it had no order at all. The step
is spelled out in WORDS now (`Direction — trend timeframe`, `Location — trade London (sweeps the
Asian high/low)`, `Point of interest — …`, `Target 1 — …`).

⚠ **The underlying tension is real and is not this file's fault: the contract groups by what a
setting CHANGES, and a sequential model's steps do not map onto that one-to-one.** Steps 1-3 are
all `4 · What arms it`; step 4 is `5 · Entry`; step 5 is `6 · Stop & targets`. **Both orderings are
right and they are different orderings**, so the panel has to carry the group number and NAME the
step — numbering it twice is what broke. Worth checking on any strategy here whose rules are a
named sequence.

⚠ **`execTp1Pct` also stops being a passenger under the palette work and is worth re-reading**: at
50 it is a real scale-out, so this file needs the "a rung is issued only while unfilled" guard that
A+ gets away without only because A+ ships both rungs at 0.

✅ **The 775-line body — engine, gate chain, entry, staged stop, exits — diffs BYTE-IDENTICAL to
HEAD apart from the two sizing lines**, which at the default `Risk % of equity` compute the
identical expression. So the panel and the palette moved and the trade list cannot have.
✅ Static checks: no tabs, brackets balanced, zero duplicate top-level declarations, zero duplicate
input titles within a group, every input grouped, and `check_active_order.py` green.

⚠ **NOT COMPILED. The file has still never been through a compiler**, and this pass touched every
input declaration and rewrote the whole drawing layer, so it is the pass most likely to have added
one. ⚠ **The first paste costs one "Reset settings to defaults"** — every input moved. **Untick
Style → "Trades on chart" in the same visit**, or the built-in markers double-draw against the new
